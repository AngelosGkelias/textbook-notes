# Resumption and optional allocation

## Reuse accepted work

Persist the source inventory, teaching specification, accepted sections, asset provenance, and check results. Link acceptance to the relevant source ranges, prerequisites, output files, and figure inputs. Reuse helper-generated records rather than duplicating them in reports.

On resume, compare hashes first. Invalidate changed concepts and their dependents; preserve unaffected sections and checks. Compare page/range evidence where feasible. Equal extracted text does not establish unchanged diagrams or annotations: reuse visual-inspection status only with matching page/render evidence, otherwise inspect changed or unproven pages. Keep overview survey, detailed inspection, and teaching acceptance distinct. Changed audience assumptions can invalidate prerequisite treatment.

## Allocate resources

Use scripts for mechanics and the configured model for reasoning. Where model/effort selection is available and authorized, choose the least costly adequate option and escalate a bounded problem when reconstruction, interpretation, or teach-back fails. Model names, account access, and valid settings come from the runtime.

Balanced is the default: ordinary authoring with selective deeper review. Economy concentrates effort on difficult or consequential material; an explicit Maximum quality request permits broader independent review and transfer probes. These modes change allocation, not substantive requirements. Save accepted work and exact remaining tasks when a resource limit interrupts progress. Record settings or usage only when exposed and relevant; unavailable telemetry remains unknown.

## Delegate only when authorized and useful

Partition by conceptual dependencies. Give each worker bounded raw source scope, audience, relevant specification/prerequisites/notation, skill path, and owned section/asset/record paths. For Typst, include theme exports, heading conventions, and an isolated build command. The lead owns shared files and integration; workers return actual artifacts, acceptance/check evidence, and unresolved issues.

For review, provide source, specification, chapter, and figures; request concrete source/output evidence and local repairs. Use independent contexts where offered. Parallelism must justify repeated context and coordination cost; a large source alone is insufficient.
