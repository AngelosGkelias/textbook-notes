# Bounded workers and reviewers

Read only when useful delegation is permitted and available. Apply [model-routing.md](model-routing.md) first. A large source does not automatically justify a team. Use independent tasks only where parallelism or independent judgment outweighs repeated context and coordination cost.

## Scope and ownership

Partition by conceptual dependencies and workload rather than equal page counts. Group tightly related concepts; make cross-section prerequisites explicit. The lead owns shared theme, main book, global notation/corrections, integration, and final build. Workers own explicit section files, an asset prefix, and their portion of the existing teaching/check records. Do not let workers race to edit shared files or produce competing whole-book plans.

Send bounded raw sources/rendered pages and relevant shared prerequisite/notation summaries, not the entire corpus to every worker. Give access to the full original when context is needed. A worker must inspect its entire assigned range, including its end, and identify distinct technical concepts rather than only headings. Do not require rereading unchanged source ranges already comprehended with hash-linked evidence; inspect raw evidence for ambiguities and review findings.

Choose supported model/effort per task; never automatically assign maximum effort. When overrides require fresh context, provide a self-contained task using the runtime's accepted fields. Honor user restrictions and report actual settings. No new sidebar tasks, external paid providers, or global setting changes are implied by internal delegation. Avoid recursive delegation unless explicitly allocated by the lead.

## Authoring assignment contract

Provide actual paths, concept/source scope, intended audience/language, source numbering convention, shared prerequisites and notation, source/research constraints, model/resource restrictions, and owned outputs. Include the skill path, relevant teaching specification, theme exports/heading levels, asset conventions, and isolated compile command/interface.

Ask the worker to:

- Confirm/refine the assigned concept teaching requirements before writing; identify overlooked mechanisms, assumptions, late content, and graphical relationships. Report cross-boundary prerequisites to the lead.
- Produce connected explanations, necessary derivations and examples, and selected visuals together. Meet each concept's understanding criteria before marking the section checked. Concision is welcome where sufficient; no quotas replace teaching adequacy.
- Preserve notation and nearby source references; label supplemental derivations/illustrative values and document corrections with evidence.
- Realize essential visual decisions, retaining a clear source figure where sufficient. Inspect actual crops and new figures at readable resolution and intended display size; verify graph meaning and schematic semantics. A suggested figure list is not a completed asset.
- Check consequential technical claims and worked results using [technical-verification.md](technical-verification.md); compile the isolated section where tooling permits.
- Return files/assets, concept destinations and acceptance evidence, source dispositions, actual checks, and unresolved issues. Keep one compact section record rather than parallel coverage/visual/verification essays.

A hard problem should return a concrete question with source location, failed criterion/check, attempted reasoning, and insertion anchor for bounded escalation. Do not restart accepted sections on a more expensive model.

## Reviewer assignment contract

Give a separate reviewer the actual source, teaching specification, chapter, and relevant figures. Assign the complete audit for a bounded source range and deeper teach-back probes for its difficult/consequential concepts, following [pedagogical-review.md](pedagogical-review.md). Do not give a desired answer or ask for generic approval. Ask for source/destination locations, failed understanding actions, missing reasoning or visuals, and local repairs. The reviewer must find defects in the specification as well as the chapter.

For a technical review, give assumptions, actual equations/diagrams, and relevant evidence; ask for reconstruction, counterexamples, or checks of critical steps. Keep pedagogical and technical findings distinguishable even if the same reviewer performs both. Match capability to difficulty rather than assigning several premium reviewers to routine definitions.

## Integration and stopping

Inspect delivered evidence and actual assets; a worker's completion message is not certification. The integrated coverage audit must account for every source page and substantive concept, including boundaries between assignments. Reconcile notation and duplicate explanations with cross-references and check links to shared prerequisites. Inspect the integrated PDF for global numbering, layout, and figure placement.

Repair findings in affected sections and dependents, then recheck failed criteria. Broaden review only for a new defect, dependency change, or systematic blind spot. Reuse accepted unchanged results. If independent review is unavailable, perform the disclosed fallback in pedagogical-review.md; do not claim an independent pass occurred.
